# Phase 5 review: dispositions

Review: `phase-5-review.md` (2026-10-29; MCP server, packaged skill, and the agent code it reaches). Every finding below
has a regression test that fails on the reviewed code and passes now. The reviewer's exploit scripts were re-run after
the fixes: the attacker "vault" now gets `unverified_vault` in 0 ms (was `ok`), and the 2 MB attestation flood makes 0
NVIDIA calls (was 202).

| # | Severity | Finding | Disposition |
|---|---|---|---|
| F1 | High | Any contract logging an `irontrade` event made `verify_receipt` say ok; policy/usage/preview/record returned attacker data as if trusted | **Fixed.** New `agent/src/provenance.ts`, shared by the CLI `verify` and every MCP vault tool. A genuine vault is a direct sub-account of a known factory (config, never tool input: testnet `arena.irontrade.testnet`, keyless, and legacy `irontrade.testnet`, flagged as still holding a key), runs the factory's pinned global code, has 0 access keys, and was initialised with the factory's exchange/intents/MPC ids. Otherwise `verify` gives `unverified_vault` without reading the vault's transactions, and the tools return `provenance.iron_trade_vault: false` with a warning that the data is untrusted. `list_vaults` reports `known_factory`. Server instructions say chain strings are data, not instructions. Tests: agent `F1: …` (3), mcp `F1: a contract that logs irontrade events but isn't a factory vault never verifies…` |
| F2 | Medium | A hostile token's `ft_metadata.decimals` (1e8) froze the server for 43 s, used 1 GB and returned 100 MB | **Fixed.** A token mismatch returns before any metadata read. Decimals must be 0–38 (`checkDecimals`, enforced in `toUnits`/`fromUnits` and in the MCP decimals source). Values in problem strings are clipped. Tests: agent `F2: …` (2), mcp `F2: a token reporting absurd decimals can't stall the server…` |
| F3 | Medium | `verifyBundle` made network calls for every model report, even when local checks had already failed (203 quote checks, 202 NRAS calls per 2 MB bundle); no timeout on PCCS fetches | **Fixed.** Network checks run only after the local checks pass: format, nonce, request, at most 8 model reports (`MAX_MODEL_REPORTS`), and the reply's signature (kind, signed text, EIP-191 signer). Then only the gateway and the report whose address signed the reply are checked. dcap-qvl uses the global `fetch`, so its wait is bounded with a 30 s deadline (`withDeadline`); the library's own sockets can't be aborted from outside. NRAS has a 30 s deadline and a 256 KB streamed body cap. Tests: `tee: with no response signature … no Intel or NVIDIA call`, `real: a bundle failing a local check makes no Intel or NVIDIA call; more than 8 model reports are refused unread`. Report-level tests now call `checkReport` directly, because the captured fixture has no signature |
| F4 | Medium | The packaged `skills/iron-trade/SKILL.md` still recommended a 0.25 NEAR allowance that blocks 300 Tgas calls | **Fixed.** Regenerated from the canonical `agent/SKILL.md` (no allowance cap, small agent-account balance). `mcp-unit` now runs in `tests/run.sh`, so the copy test blocks a stale copy. Test: `skill: the packaged copy matches the canonical agent/SKILL.md` |
| F5 | Low | Events from failed (reverted) receipts counted as decisions | **Fixed.** Only receipts whose status is `SuccessValue`/`SuccessReceiptId` count, in MCP records and receipts and in the CLI `verify`. A missing status doesn't count. Dropped logs are reported as `failed_receipt_events`. Both RPC and the FastNEAR transactions API return the status (checked live). The arena's own view of its transactions is unchanged. Tests: agent `F5: verify counts only events from receipts that succeeded`, mcp `F5: …` |
| F6 | Low | The 8 MB cap was checked after buffering the whole body, and counted characters, not bytes | **Fixed.** A declared `content-length` over the cap is refused unread; the body is streamed and the read is cancelled as soon as it passes 8 MB (bytes). Test: `F6: an oversized body is refused while it streams…` |
| F7 | Low | HTTP: no Origin check; a stateless GET held an SSE stream open forever; no concurrency cap | **Fixed.** `httpGate`: only `POST /mcp`; Host must be loopback on our port; any Origin other than our own loopback origin gets 403; GET/DELETE get 405; more than 8 concurrent requests get 503. `headersTimeout` 10 s, `requestTimeout` 30 s, and each request is closed after 120 s. The SDK's (deprecated) DNS-rebinding option stays as a second layer. Tests: `F7: the HTTP gate…`, `F7: the live HTTP server refuses a forged Origin and a GET stream` |
| F8 | Low | The server imports the crypto libraries from `agent/node_modules` without declaring them; the npm name isn't registered | **Partly fixed, rest kept for publish.** `@phala/dcap-qvl`, `@noble/curves` and `@noble/hashes` are now declared and pinned in both `mcp/package.json` and `agent/package.json` (the agent imported `@noble/*` only transitively). Node still resolves `agent/src`'s imports from `agent/node_modules`, so `mcp-unit` installs the agent's dependencies first. **Kept:** a self-contained esbuild bundle and dropping `tsx` from runtime deps are publish steps. The npm name must be registered before `server.json` is published (mcp/README "Publishing"). `package.json` stays `private: true` |
| F9 | Info | The "no keys" test scanned only `mcp/src`, not the agent modules it imports | **Fixed.** Test `F9: the server's import graph reaches no key-handling module` walks value imports from `server.ts` and fails if it reaches `near-api-js` or `agent/src/{config,vault,models,main,arena,attest/nearai}`. `provenance.ts` has no side-effect imports |
| F10 | Info | `verify_attestation` without a receipt could be read as proof of a vault decision | **Fixed.** Every result carries `proves`, saying what it does and doesn't establish. NRAS JWT signature validation is **kept** as a known gap (documented in mcp/README) |
| F11 | Info | `elliptic` low advisory via dcap-qvl | **Kept.** dcap-qvl uses elliptic only to verify signatures, not to sign, so the advisory doesn't apply. `npm audit fix --force` would downgrade dcap-qvl to 0.2.0. Track upstream. The advisory now also appears in `mcp/` (same dependency, declared) |
| F12 | Info | Mainnet accepted only `*.near` and 64-hex ids | **Fixed.** On mainnet any valid id that isn't `*.testnet` passes the id check. Whether it's a vault is now the provenance check's job. Test: `F10 … F12: mainnet ids under any top-level account pass the id check` |
| F13 | Info | The skill said "fixed code only" but suggested free text after `refused:` | **Fixed.** `agent/SKILL.md` (and its copy) now says exactly `refused:<code> <buy|sell> <decimal amount>` with no other text, matching what `verify` expects |
