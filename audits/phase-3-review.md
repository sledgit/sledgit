# Phase 3 review: house strategies ("Open rules"), Luck baseline, computed benchmarks

Scope: `agent/src/strategies/rules.ts`, `market.ts`, `benchmarks.ts` (new); the `house` and `house-rerun` commands in
`agent/src/main.ts`; the `market` input in `agent/src/arena.ts`; the `rules` provider in `agent/src/models.ts`;
`agent/test/strategies.test.ts`; data `deploy/testnet/receipts-house/` and `arena-1793252769.json`. The site entries
that present these vaults (`site/src/lib/networks.ts`, `site/src/lib/bots.ts`) were read because they carry the public
claim. The attestation hunks in `main.ts` belong to another change set and were not reviewed.

Claim under test: house entries are deterministic strategies whose hash (sha256 of a canonical spec that includes the
sha256 of `rules.ts`) is in every receipt, so anyone can re-run any tick from its receipt and get the same decision;
Luck is random but seeded and re-runnable; Hold and Stake & hold are computed benchmarks at a stated APR.

Method: code reading. `house-rerun` on the three published receipt files. Attack scripts run offline against the real
code (forged inputs, CRLF source, history window, luck seed grinding, breakout under caps). The recorded candles and
reference price were cross-checked against Binance's public klines. Read-only RPC (`https://rpc.testnet.fastnear.com`):
`view_access_key_list`, `view_account`, `get_config`. Key files: permissions only (`ls`), contents not read. No
transactions were sent and no repo file other than this report was changed.

## What held up

- **Re-run works on the real data.** `house-rerun` on all three published files (9 receipts): `hash_match: true, same: true` everywhere, exit 0. Editing `model_output` or `prompt_sha256` is detected (unit test plus manual check).
- **The inputs came from the published feed.** Trend receipt 1's 60 candles match `data-api.binance.vision/api/v3/klines?startTime=1788048000000&limit=60` exactly (60/60, high/low/close byte for byte). The last bar (2026-10-28) is closed. The reference price 4.466 is inside the 1-minute high/low (4.464–4.467) at `fetched_at`. The source URL is recorded. Closed daily candles are immutable, so this cross-check is cheap for anyone; it just isn't automated (P3-3).
- **Hash canonicality.** `canonical()` sorts keys and uses JS number formatting (`0.10` becomes `0.1`, the same as JCS for these values). The spec hash is stable across runs and distinct per strategy. `decide()` is pure and reads only recorded inputs. JS float arithmetic, `toFixed` and the summation order are deterministic, so the re-run is exact in Node.
- **Strategies cannot exceed the vault policy.** Sizes are `min(target, balance, per-trade cap, 24 h room)` and are floored to 6 decimals, never rounded up. `min_amount_out` is the policy band, never 0, and the contract raises it to `max(min_out, quote×(1−max_slippage_bps), band)` before the swap. The contract re-checks every cap.
- **On-chain keys (read-only RPC, final).** `house-{rebalancer,trend,luck}.arena.irontrade.testnet` have **0 access keys**. They run global contract `5ePvrzPrKn8W…`, the same as `perf.arena`. Each `get_config.agent_id` is its own agent. Each `agent-house-*.it1793205219-owner.testnet` holds **exactly one** FunctionCall key with `receiver_id` set to its own vault and methods `request_swap, request_intent_swap, log_skip, intents_cancel, intents_settle, freeze`. There is no full-access key and no contract on the agent accounts. Vault `seq` is 3 for each, equal to the receipt count, so there are no unpublished ticks.
- **Key files.** `~/.config/iron-trades/testnet-agent-house-*.json` are mode 0600, in a 0700 directory. Contents were not read.
- **No secrets in the data.** No `ed25519:` private keys, API keys, bearer tokens or home paths in `receipts-house/` or `arena-1793252769.json`. The receipts contain public account ids, tx hashes and Binance URLs only.
- **Tests.** `agent/test/strategies.test.ts`: 13/13 pass.
