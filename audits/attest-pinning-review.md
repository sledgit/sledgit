# TEE attestation verifier: adversarial review (pinning, binding, pill)

Scope: `agent/src/attest/{verify,policy,pill,evidence,nearai}.ts`, `nearai-policy.json`, `POLICY.md`, the
`attest-policy` and `verify-attestation` commands in `agent/src/main.ts`, `agent/test/attest.test.ts`, the fixtures in
`agent/test/fixtures/nearai/`, and the recorded season in `deploy/testnet/receipts-arena/qwen36-tee/`. Reference: NEAR AI
`nearai/docs` `cloud/verification/**` (fetched 2026-10-29).

Method: code reading; PoC scripts against the real recorded bundles with live Intel collateral (Phala PCCS) and live
NVIDIA NRAS; four keyless calls to `GET /v1/attestation/report` (two for Qwen3.6, one for Qwen3.8, one via
`attest-policy`); a synthetic-enclave harness (own secp256k1 key, stubbed quote verifier, synthetic policy, same
shape as the test suite) for paths that need a signature NEAR would not give us. No transactions, no API key, no
repo files changed. Baseline: `node --import tsx --test test/attest.test.ts` gives 28/28 passing.

Threat model: the party who wants the badge without earning it is usually the **agent operator**. That party writes
the receipts, picks the salt, chooses the request bytes, sets the receipt `ts`, and decides which receipts go into the
season file. An outside party with its own Intel TDX + NVIDIA CC hardware is the second adversary.

## What held up

- **Attacker-owned TDX + NVIDIA hardware cannot earn the pill.** All measured values can be spoofed there (A4), but
  the reply must be signed by the pinned per-model key `0xfdbd…8ddf`. That key is released by NEAR's KMS, and its
  quote binds it through report_data. A gateway key or any other key fails the "model evidence for the signer" check,
  the model policy (app-id/compose) and the signer pin.
- **A gateway-kind signature relabelled `provider_tee`:** the gateway's address isn't a model report, and a gateway
  report placed in `model_attestations` fails the model compose/app-id pins and the signer pin.
- **Intel quote handling:** dcap-qvl 0.7.0 checks the Intel root chain and the QE identity, rejects revoked/invalid
  TCB, and refuses debug TDs by default. On top of that the verifier accepts only `UpToDate` and checks `TD_ATTRIBUTES`
  bit 0 itself. `td()` requires an `rtMr3` field, so SGX quotes are refused. PCCS errors and timeouts become
  `ok:false`.
- **report_data** = 20-byte address ‖ 12 zero bytes ‖ nonce. The echoed nonce and the GPU payload nonce are compared.
  **MRCONFIGID** = `01‖sha256(app_compose)‖0¹⁵`, and the `compose-hash` event must also equal `sha256(app_compose)`.
  **RTMR3 replay** checks each digest it is given, and tampering with a payload or reordering events breaks it.
- **Signature checks:** EIP-191 recovery with the length check and v ∈ {27,28,0,1}. The signed text is rebuilt from
  the exact request and response bytes and must match exactly. Changing the model id, a reply byte or the vault fails.
  The signer must match exactly one verified report.
- **Mixing reports across sessions:** every report must carry this bundle's nonce. Because reports are keyless this
  adds nothing for the operator (A2), but it doesn't fail open.
- **Fail-closed accounting:** `ok: null` (offline NRAS) is never counted as a pass. The pill needs `checks.length > 0`
  and every `ok === true`. Bundles that fail local checks skip all network calls. `MAX_MODEL_REPORTS` = 8 and
  `Object.hasOwn` on the model lookup hold. Both PCCS and NRAS calls have deadlines and size caps.
- **JSON/number edge cases:** the only number with a security role is `created` (integer seconds, inside the signed
  bytes). Bundle files are re-canonicalised before hashing, so formatting variants map to the same sha. Response
  duplicates are enclave-produced, not attacker-controlled. Request duplicates are covered by A3's fix.
- **`attest-policy` can't widen the policy** (A13). There is no CLI override of the policy, and `verify-attestation`
  always uses the shipped JSON.
