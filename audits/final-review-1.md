# Final pre-mainnet review 1 (mainnet gate step 6, part 1)

Date: 2026-10-29. Scope: owner web app (`site/`), posting cards (`posting/`), daily ops and monitor (local ops tree),
the agent-host container definition (local ops tree), and the key-handling examples (`contracts/vault/examples/`).
Method: read every file in scope, compared each transaction builder with the contract (`contracts/vault/src`,
`contracts/factory/src`), inspected the production bundle in `site/out`, ran `npm audit`, read-only RPC checks on
testnet and mainnet, and read-only host checks (unit state, nft table, `ls -l` of the secrets dir, socket modes).
Nothing was signed, sent or modified. Prior audits were used only to check for regressions; none of the findings
below repeats an earlier one.

Severity: High = loss of funds or keys is plausible; Medium = a protection can be bypassed or a check fails open
or silently; Low = defence in depth, misleading output, or needs an unlikely precondition; Info = note only.

Note on public text: the ops and container findings (B2-B6, C1-C5) are about a local-only tree. Proposed public
wording for them must not name host paths, host names or the container; say "the agent host" and "the daily job".

## What holds

Owner app (A):
- **Receiver integrity.** Every `receiverId` is the factory or token ids from static config, or a vault id that must match `^[a-z0-9-]{2,32}\.<factory>$`. The e2e test checks that `?v=evil.attacker.testnet` renders no tx cards. The factory `arena2.irontrade.testnet` has 0 keys (RPC) and deploys vaults by global-contract hash, so every `<name>.<factory>` is genuine factory code. Owner actions are enabled only when the connected account equals the on-chain `owner_id`.
- **Deposits and gas match the contract.** Every `assert_owner` method gets exactly 1 yocto. `exchange_storage_deposit` gets 0.1 NEAR (the contract wants >1 yocto). `apply_policy` and `intents_settle` get 0 and are non-payable. Gas is at or above each `TG_MIN_*`: exchange_withdraw/claim 150 ≥ 120, intents_cancel 300 ≥ 255, intents_settle 100 ≥ 60. `ft_transfer_call` goes to the selected wrap token with `receiver_id` = the vault, and the vault's `ft_on_transfer` refunds anyone but the owner.
- **Units and price math.** Units are exact bigint, with no floats, and reject signs, exponents and excess precision. The price-floor conversion is right across 24 and 6 decimals: mainnet sell floor 3.0 → 3/10^18, so 1 wNEAR → ≥3 USDC; buy floor 0.17 → 0.17 wNEAR per 1 USDC. Mainnet config checked on chain: pool 4512 = USDC/wNEAR, wNEAR 24 decimals, USDC 6 decimals. Defaults sit about 30% from the pool price (≈4.42 USDC/NEAR today).
- **The contract checks are mirrored.** `validatePolicy` mirrors `Policy::validate` and adds a u128 bound. `create_vault` sends `owner_id` = the signer, which the factory requires.
- **No key enters the page.** Sign-in creates no function-call key (no `contractId`), so the wallet confirms every tx. Hardware wallets are refused.
- **No XSS found.** All chain and URL data is rendered as React text. The only `dangerouslySetInnerHTML` is static JSON-LD. Explorer links are prefix-built from validated ids, and returned hashes are base58-filtered.
- **Redirect handling.** No open redirect in the app, and wallet return params are stripped after reading. The passcode gate's `safeNext` blocks `//`, `\` and control characters.
- **Test hook compiled out.** The production `site/out` has no mock hook: `MOCK` is inlined as `""`, and the wallet chunk goes straight to the selector.

Posting (B):
- No free text: cards use fixed templates, registry names, contract refusal codes and numbers. `u-` (unregistered) entries are excluded.
- The SVG escapes every value, and `checkText` enforces ≤280 characters, no links and the forbidden-terms list.
- The stamp is derived from the snapshot and is mismatch-checked. On testnet that check works; see B5 for mainnet.

Daily job and monitor (B):
- **No unchecked snapshot ships.** The build goes to a staging dir and the repo files change only after `league check` passes (two tries). The site build reads only those checked files, and the deploy happens only after that. The live hash is compared afterwards.
- **No secrets on disk or in logs.** The keychain passcode never reaches a file or the log, and today's logs hold no secrets.
- **Read-only monitor.** The monitor sends RPC views and runs `systemctl show` over ssh with fixed arguments, using `execFileSync` rather than a shell. It strips `"` from notification text.

Agent-host container (C):
- **Secrets stay out of the store and the journal.** The flake carries no secrets. `stage.sh` copies only source plus the lockfile and refuses key-shaped content. Keys reach the services through `LoadCredential` from a 0400 root-owned store (confirmed with `ls -l` on the host), and the agent redacts every key form before logging.
- **Egress for TCP/UDP from uid 510.** Only 127.0.0.1:8888 is allowed. `NoNewPrivileges` blocks file-capability helpers (ping).
- **NEAR AI spend guard.** `--ticks 1` makes exactly one `complete()` per tick, with no SDK retries (`maxRetries: 0`; the retries are only signature GETs). The unit has `Restart=no`, `Persistent=false`, and is skipped when the key file is missing. `pull.sh` never copies `secrets/`.

Examples (D):
- **Key files.** New keys are written 0600 with `create_new`, so an existing file is never overwritten. The scoped agent key is saved before it is added, and the function-call key's exact receiver and methods are checked afterwards.
- **Factory lock.** The factory lock refuses unless the only key is the pending key, then deletes it and proves 0 keys remain.
- **Testnet guards.** All three examples refuse anything but `.testnet`. Results files hold no secrets.

## Gate verdict for part 1

No High findings. Before mainnet, fix C1 and C2 (the agent host can leak or redirect keys if the agent process is ever compromised), A1 (the timelock display), and B1 (deploy integrity). A2, A6, A7 and B5 should land before mainnet opens to outside owners. The rest can be scheduled.
