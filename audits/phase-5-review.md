# Phase 5 security review: read-only MCP server and packaged skill

Scope: `mcp/` (server, NEAR client, tools, transports, packaging) and `skills/iron-trade/SKILL.md`, plus the `agent/src`
code reachable from the server (`receipt.ts`, `verify.ts`, `decision.ts#toUnits`, `attest/{pill,evidence,verify}.ts`,
and `@phala/dcap-qvl` collateral fetching). Method: code reading, `npm ci && npm test && npm audit` in `mcp/` and
`agent/`, local exploit scripts with mocked RPC, a local HTTP-transport probe on 127.0.0.1, and two read-only RPC
views on testnet. No transactions, no keys.

Test run: 21 tests, 20 pass, 1 fail (`skill: the packaged copy matches the canonical agent/SKILL.md`, see F4).
`npm audit`: `mcp/` 0 findings; `agent/` 2 low (`elliptic` via `@phala/dcap-qvl`, see F11).

## Checked and found clean

- **No path to signing or writing.** The server's whole import graph has no key material, no `near-api-js` and no `send_tx`/`broadcast_tx`. Every RPC method is `query` (`call_function` views, `view_access_key_list`, `view_account`) or `tx` (read). View calls can't change state. Agent `config.ts` (which loads secrets) isn't reachable. The tools are annotated read-only.
- **SSRF / user-controlled hosts.** All hosts are constants: the FastNEAR RPC and tx API, Phala PCCS, NVIDIA NRAS. Account ids, tx hashes and token ids go only into JSON bodies. In dcap-qvl, the URL parts taken from the quote are hex FMSPC and a fixed `processor`/`platform` CA. The root CRL URL comes from the PCCS-returned issuer chain, not from the bundle.
- **Input validation.** Zod schemas cap lengths (account ≤ 64, receipt 64 KB, bundle 2 MB). `checkAccount` follows NEAR id rules plus a network suffix, and its regex isn't vulnerable to ReDoS (the length check runs first; pathological inputs take 0 ms). Amounts are `^\d{1,39}$` with a `< 2^128` BigInt check, and a zero `min_amount_out` is refused. `tx` is base58 with 43-44 chars. Pagination is bounded (`accountTxs` stops at `max ≤ 200`, empty pages and a missing resume token break the loop; `txs` makes at most 10 batches). Every request has a 20 s deadline. The SDK caps HTTP request bodies at 4 MB (verified: 10 MB → 413-style error).
- **Event spoofing within a transaction.** `vaultEvents` keeps only logs whose `executor_id` is the vault, so a token or exchange in the same tree can't forge events (and a test covers this). The F1 caveat is about *which* account counts as the vault.
- **Receipt hashing.** The hash is taken over the raw stored line (only one trailing `\n`/`\r\n` stripped). A non-canonical line (duplicate keys, whitespace, a stray `\r`) is flagged and gives `mismatch`. `receipt.network` must equal the tool's network. The event must be `request`/`refuse`/`skip` with that exact `receipt_hash`. A `hold` must match a `skip`, and `buy`/`sell` must match `token_in` and `amount_in`.
- **Attestation fail-closed.** Every check must be `ok === true`, so `null` (NRAS unavailable) and exceptions both mean no pill. Malformed bundles (a missing `report`, bad hex, a bad event log) throw or fail a check, never pass. The binding checks run before the crypto. The TCB status must be `UpToDate`, and debug mode must be off. The report data must bind signer and nonce, MRCONFIGID must equal `app_compose`, and RTMR3 is replayed from the event log. The GPU nonce must match before NRAS is called. The EIP-191 signer must equal exactly one fully verified model report.
- **HTTP binding.** The server binds `127.0.0.1` only. A Host header other than `127.0.0.1:<port>`/`localhost:<port>` gets 403 (DNS rebinding blocked, verified). `text/plain` gets 415 and a preflight gets 405 with no CORS headers, so a browser page can't send a JSON-RPC request. Paths other than `/mcp` get 404. The port is checked to be 1024-65535.
- **Error handling.** Tool failures come back as `isError` results with a one-line message (host plus the first 160 chars of an endpoint error). No stack traces, no environment, no file paths. No bare `catch` swallows a verification failure: the catches in `bindingChecks`/`checkReport` record `ok:false`.
- **Secrets.** There are no keys, tokens or credentials in `mcp/` or `skills/`. `OWNER` is a placeholder. The smoke test reads only `IRON_TRADE_MCP_LIVE`/`IRON_TRADE_MCP_VAULT`.
- **Dependencies.** `mcp/` pins exact versions with a lockfile (127 packages) and `npm audit` finds 0 issues. The only install scripts are `esbuild` (via tsx) and the optional `fsevents`. `npm ci --ignore-scripts` works.
- **SKILL.md numbers checked against the contract.** `request_swap` min 235 Tgas (`TG_MIN_REQUEST`), `request_intent_swap` min 230, `intents_cancel` min 255, note ≤ 280 bytes, `freeze` callable by the agent with no deposit, `intents_settle` at 100 Tgas covers its 10+10 Tgas chain. The advice to use a FunctionCall key, not FullAccess, is right. The only wrong part is the allowance advice (F4).
