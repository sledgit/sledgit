# Final pre-mainnet review 2 (mainnet gate step 6, part 2)

Date: 2026-10-30. Independent and adversarial. Scope: everything changed since audit round 3:
(1) Season 1 mainnet tooling (`contracts/vault/examples/season1_mainnet.rs`, `deploy/mainnet/*`, the mainnet pair in
`agent/src/pairs.ts`, `FACTORIES.mainnet` in `agent/src/provenance.ts`); (2) the league reader incl. the by-model view
(`agent/src/league/*`), the season-check cutoff (`agent/src/attest/season.ts`) and `league check`; (3) the local tick
runner for self-hosted models (local operations tree, not published); (4) the site: by-model view, theme toggle, the
"Attested model" pill, canonical/OG, the owner app's latest changes; (5) the testnet suite (`testnet_suite.rs`);
(6) a claim check of the public copy (README, site, `llms.txt`) and a private-name scan.

Method: read every file in scope, formed a view before reading the earlier audits, then checked for regressions. Read-only
RPC on testnet and mainnet. Offline PoCs ran only against copies in a scratch directory. Nothing was signed or sent, no key
file was read, and no repository file was modified except this report. Ran `tests/run.sh --quick`, the agent/MCP/site
suites (inside it), the `season1_mainnet` example's unit tests, and `league check` on the committed testnet snapshot.

Severity as in part 1: High = loss of funds or keys is plausible; Medium = a protection or a public claim can be
defeated or fails silently; Low = defence in depth, misleading output, or needs an unlikely precondition; Info = note.

## What holds

Season 1 tooling:
- **The mainnet pair is right on chain.** `17208628…36133a1` is native USDC, `ft_metadata` decimals 6, symbol USDC. `wrap.near` has 24 decimals. Rhea pool 4512 (`v2.ref-finance.near`) is a SIMPLE_POOL of exactly [USDC, wrap.near], fee 30 bps (matches `benchmark_cost_rate` 0.003), price ≈ 4.49 USDC/NEAR today. Both tokens' `storage_balance_bounds` are 0.00125 NEAR (= `FT_STORAGE`), and Rhea's min is 0.00102 (< `EXCHANGE_STORAGE` 0.02). `PAIRS.mainnet`, the season example and `deploy/mainnet/league/entries.json` agree, and a test pins it.
- **Plan is the default and is read-only.** Sending needs `IT_ENTRY` and `IRON_TRADE_MAINNET_CONFIRM` equal, the RPC's `chain_id` equal to the config's network, and no factory/entry/shared-key problem. One entry per run.
- **Separation.** An account in two entries, an owner that is also an agent, or an entry account equal to the factory, its parent or a vault is refused, and so is any shared public key (blocking). Each owner-side transaction is signed by that entry's owner, and each key step by that entry's agent (unit-tested).
- **The agent ends with exactly one function-call key** (the vault, the 6 agent methods, non-null allowance) and no full-access key. `agent_done` is exact (unit tests), and the post-check re-reads the chain. The testnet rehearsal (`s1-rehearsal.arena2.irontrade.testnet`) shows exactly that: 1 FC key, allowance 1 → 0.9955 NEAR after 2 calls. The vault has 0 keys and the right owner and agent.
- **Funding math.** Raw amounts are exact (no floats in the plan), excess precision is refused, and price bands round to the vault's ceil formula (unit tests: 1.2 wNEAR at 3.0 → 3.6 USDC; 5 USDC at 0.17 → 0.85 wNEAR). An overflow at the cap is refused. Owner NEAR = deposit + storages + wrap + 0.02 gas; the last prepaid-gas step still fits. The bands sit about 33% under and 31% over today's pool price.
- **Key files.** Group/world-readable key files are refused. The new agent key is written 0600 with `create_new` before it is added, and agent function-call files never sign setup steps.

League and attestation:
- **Proof tiers are separate rows**, and fixtures, retired and unregistered vaults never enter a group (tests). The view is deterministic (code-point order, no locale), and `-0` and non-finite numbers are handled.
- **Model-id normalisation can't move an entry into another tier**, and the strategy names are reachable only through a `rules:` prefix. Unknown ids pass through unchanged, case-sensitive, so the worst case is a split row, not a merged one.
- **The cutoff fix works as stated.** Decisions after `toSeq` are dropped, and a decision the indexer missed (either side of the cutoff) leaves the counter above what was read, which fails closed (see F2-16 for the tail case).
- **The TEE season checks** (seq coverage up to the vault's own counter, evidence reuse, per-decision binding) are unchanged since round 3 and still pass on the committed season. `verify` on `s1/receipts-arena/qwen36-tee` gives seq 1 skip, seq 2 request, seq 3 skip, all `ok`, `iron_trade_vault: true`, which matches README's seq-1 claim.

Site:
- **No XSS found in the new code.** The by-model table renders snapshot strings as React text, and its links are `/agents/<id>/` from registry ids. The theme pre-hydration script is a static string: it only ever sets `data-theme` to `"light"` or `"dark"` (anything else in localStorage is ignored), so it can't carry injected content. The CSP has no `script-src` (A6, kept), so it runs. When `script-src` is added, pin this script's sha256 (it never changes per page).
- **The security headers are unchanged** (`frame-ancestors 'none'`, XFO DENY, nosniff, referrer policy) on static files and on the gate's own pages.
- **The owner app's latest changes** (the A1-A5 fixes) hold. `diffPolicy` marks a lowered floor, a raised cap/rate/slippage, a new token/pair or a pool change as weaker. `formFromPolicy` refuses any policy it can't represent exactly. `checkAgent` refuses a missing account or the owner/vault/factory, and warns on deployed code or no keys.
